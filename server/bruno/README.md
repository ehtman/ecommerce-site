# bruno/: Bruno collection (optional)

Bruno is an open-source, offline API client. Requests are plain-text `.bru` files, so they live in git like code.

| Path                           | What it is                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bruno.json`                   | Collection definition ("ShopEase API")                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `environments/local.bru`       | `baseUrl`, `mailpitUrl`, `adminEmail`, `adminPassword` (+ variables the scripts fill)                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `01 Auth/*.bru`                | The auth story in order: health → register → read verify email (Mailpit) → verify → login → me → forgot → read reset email → reset → login → change password → logout → admin login                                                                                                                                                                                                                                                                                                                            |
| `02 Profile & Addresses/*.bru` | Self-contained: register + verify a fresh customer (Mailpit) → profile get/update (mass assignment ignored, bad phone 400) → addresses: create, default rules, update, 400s, fill to 5, 6th refused → second customer gets 404 on my address (ownership) → admin gets 403 → delete default, newest takes over                                                                                                                                                                                                  |
| `03 Categories/*.bru`          | Self-contained, no email: admin login + fresh customer → create (slug) → 409 duplicate in another case → 400 → customer 403 / no token 401 → sub-category → third level 400 → public list and get by slug → rename (old slug 404) → deactivate (public 404) → delete parent with child 400 → clean-up deletes → 404 → malformed id 400                                                                                                                                                                         |
| `04 Products & Uploads/*.bru`  | Self-contained: admin login + a fresh customer (for 403s) → own category → products A, B (sold out), C (inactive) → 409 duplicate SKU, 400, 401, 403 → list by category / sort + page / price / keyword / inStock (inactive never shown) → brands → by slug, inactive 404 → update, stock, image removal → upload guards (400/401/403, no Cloudinary keys needed) → category in use 400 → deletes everything it made                                                                                           |
| `05 Cart & Wishlist/*.bru`     | Self-contained: register + verify a fresh customer (Mailpit search by recipient, newest message) → admin login → create a category and products A, B (stock 3) and inactive C → cart: empty, add with fake price (ignored), add again (quantities add), over 10 → 400, over stock → 400, inactive → 404, invalid → 400, set quantity, free shipping from Rs 5,000, not in cart → 404, 401, admin 403, remove, clear → wishlist: add, add again (idempotent), inactive 404, bad id 400, admin 403, remove twice |
| `06 Coupons/*.bru`             | Self-contained: admin login → category + product → create coupons (409 duplicate in lowercase, 400 for 95%) → list/get/deactivate/400/404 → fresh customer registers + verifies (Mailpit **search** by address, newest message) → customer 403 on list → preview: empty cart, below minimum, 20% capped at Rs 500, disabled, unknown, no code, 401, admin 403 → admin deletes                                                                                                                                  |
| `07 Orders/*.bru`              | Self-contained checkout: admin creates a category + product (stock 2) → fresh customer registers, unverified order → 403, verifies (Mailpit search by recipient) → address → empty cart 400 → cart → COD order (totals, stock 0, confirmation email) → my orders / detail → admin invalid jump 400 → confirm → customer cancels (stock back) → second order walked to delivered (tracking required) → other customer 404, admin 403, customer on admin route 403                                               |
| `08 Payments/*.bru`            | Self-contained, no live Stripe needed: health shows `cardPaymentsEnabled` → register + verify a customer (Mailpit **search by recipient**, newest id) → checkout session 401 / 400 invalid id / 400 cards off / 403 admin → CARD order refused while cards are off → webhook without or with a fake `Stripe-Signature` → 400 → expiry job: no secret 401, wrong secret 403, login token 403, Bearer secret 200, POST + `x-cron-secret` 200                                                                     |

**Before running:** API running, Mailpit running, admin seeded, `RATE_LIMIT_ENABLED=false`, and `CRON_SECRET` in `.env` equal to the `cronSecret` variable (`test-cron-secret`, folder 08). (Folder 04 does not need Mailpit or Cloudinary keys.)

- App: Open Collection → select this folder → environment **local** → run the collection (or one folder).
- Terminal: `npm run test:bruno`.
