# postman/: Postman collection

| File                                      | What it is                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ShopEase.postman_collection.json`        | All requests, one folder per module (**01 Auth**, **02 Profile & Addresses**, **03 Categories**, **04 Products & Uploads**, **05 Cart & Wishlist**, **06 Coupons**, **07 Orders**, **08 Payments**, **09 Reviews**). Each request has test scripts.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `ShopEase.local.postman_environment.json` | Environment "ShopEase – local": `baseUrl`, `mailpitUrl`, `adminEmail`, `adminPassword`, plus variables the scripts fill (`email`, `password`, `token`, `oldToken`, `adminToken`, `verifyToken`, `resetToken`; folder 02: `customerEmail`, `customerToken`, `otherEmail`, `otherToken`, `addressId`, `addressId2`; folder 03: `categoryName`, `categoryNameUpper`, `categoryId`, `categorySlug`, `oldCategorySlug`, `childCategoryId`; folder 04: `productRunId`, `categoryId`, `categorySlug`, `productId`, `productSlug`, `product2Id`, `inactiveId`, `inactiveSlug`, `imageId`, `image2Id`; folder 05: `cartEmail`, `cartToken`, `mailId`, `cartCategoryName`, `categoryId`, `cartSkuA`/`B`/`C`, `productId`, `productId2`, `inactiveProductId`; folder 06: `couponEmail`, `couponToken`, `couponMailId`, `couponCategoryName`, `couponCategoryId`, `couponSku`, `couponProductId`, `couponCode`, `couponCodeLower`, `couponId`, `couponCode2`, `couponId2`; folder 07: every variable starting with `order`, e.g. `orderToken`, `orderAdminToken`, `orderProductId`, `orderId`, `orderNumber`; folder 08: `cronSecret` (must equal `CRON_SECRET` in `.env`), `cardEnabled`, `paymentsEmail`, `paymentsToken`, `paymentsMailId`; folder 09: `reviewStamp`, `reviewCategoryId`, `reviewProductId`, `reviewProductSlug`, `reviewCustomerEmail`, `reviewMailId`, `reviewVerifyToken`, `reviewCustomerToken`, `reviewAddressId`, `reviewOrderId`, `reviewId`). |

**Before running:** API running, Mailpit running (`docker compose up -d`), admin seeded, `RATE_LIMIT_ENABLED=false` and `CRON_SECRET=test-cron-secret` in `.env` (folder 08).

- App: Import both files → choose the environment → run the whole collection (or one folder) in the Runner.
- Terminal: `npm run test:api` (Newman).

Every folder is **self-contained**: folder 02 registers and verifies its own customer, registers a second customer to prove it cannot touch the first one's addresses (404), and logs in the admin to prove admins get 403. Its "fill up to 5" request uses `pm.sendRequest` in a pre-request script to add the 3rd and 4th addresses, so the next request can check that the 6th is refused.

Folder **03 Categories** needs no email: it logs in the seeded admin, registers a fresh customer (the register response already contains a token, enough for the 403 checks) and uses `'Postman Cat ' + Date.now()` as a unique name per run. It checks slug generation, the case-insensitive 409, the two-level rule, public vs inactive, rename → new slug (old slug 404), "can't delete a parent with children", and deletes everything it created.

Folder **04 Products & Uploads** logs in the seeded admin, registers its own customer (for the 403 checks), creates its own category and three products (one inactive) with names that contain a run id (`pm<Date.now()>`), so it can run again and again. It checks filters, keyword search, sorting, pagination, stock and image removal, the upload guards (no Cloudinary keys needed: it only tests 400/401/403), and then deletes everything it created.

Folder 05 registers and verifies its own customer, then logs in the seeded admin (`adminEmail`/`adminPassword`) and creates a category and three products through the API (unique names and SKUs from `Date.now()`), so it needs nothing from earlier folders. It walks the whole cart (fake price ignored, quantities add up, max 10, stock limit, inactive 404, free shipping from Rs 5,000, 401/403, remove, clear) and the wishlist (idempotent add and remove).

Folder 05 reads its verification email with `GET /api/v1/search?query=to:<email>` and then the NEWEST message by id (`/api/v1/message/{{mailId}}`), because Mailpit may be shared with other test runs. The older folders' "Mailpit – read … email" requests fetch `GET /api/v1/message/latest` from Mailpit and save the token from the link, so the email flows run without manual copying.

Folder **06 Coupons** is self-contained too: the admin creates a category, a product and two coupons (409 for the same code in lowercase, 400 for 95%), a fresh customer registers and verifies, fills the cart and previews coupons (empty cart, minimum order, 20% capped at Rs 500, disabled, unknown, 401, admin 403), then the admin deletes them. Because Mailpit is shared, it finds the email with `GET /api/v1/search?query=to:<address>` and reads the **newest** match by id instead of `message/latest`.

Folder **07 Orders** reads Mailpit with `GET {{mailpitUrl}}/api/v1/search?query=to:{{orderEmail}}` and takes the **newest** message id, then `GET /api/v1/message/{id}`. Searching by recipient is safe even when other test runs share the same Mailpit (`latest` could be someone else's email).

Folder **08 Payments** needs no Stripe account: it checks the answers while card payments are OFF (checkout 400, CARD order 400), that the webhook refuses a missing or fake `Stripe-Signature` (400), and the expiry job's secret (401 none, 403 wrong or a login token, 200 with `Authorization: Bearer {{cronSecret}}` like Vercel Cron, 200 with `x-cron-secret`). If the server runs with real Stripe keys (`cardPaymentsEnabled: true`), the card checks expect 404 for the made-up ids instead. Because Mailpit is shared, it finds its verification email with `GET /api/v1/search?query=to:<email>` and reads the newest message by id. The real paid flow is tested by Jest (signed test webhooks) and by hand with the Stripe CLI (docs/modules/08-payments.md).

Folder **09 Reviews** builds its whole story itself: the admin creates a category and a product, a fresh customer registers, verifies, adds an address, fills the cart and places a COD order, and the admin moves the order through every valid status to `delivered`. Only then is the review accepted; the folder then checks 401/403/400/409, the product's `ratingAverage`/`ratingCount` after create, edit, hide and delete, and the admin moderation list.

Folder 09 reads its email with `GET /api/v1/search?query=to:<email>` and then opens the NEWEST message by id. That is safe even when other test runs send mail to the same Mailpit at the same moment.
